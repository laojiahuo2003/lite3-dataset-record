# ScribeMem-Bench：面向具身智能记忆系统的巡检场景评测基准

## ScribeMem-Bench: An Embodied Memory Benchmark for Real-World Robotic Inspection Scenarios

---

**摘要**：具身智能体在长程任务中需要可靠的记忆系统来记录、检索和利用历史经验，然而当前缺乏面向真实巡检场景的标准化记忆评测基准。本文提出 **ScribeMem-Bench**——首个基于真实具身巡检场景的记忆系统评测基准。该基准以"真实巡检场景"为场景蓝本，通过具身机器人/机器狗在真实环境中录制多模态视频流，构建包含场景记忆节点、视觉证据和时空标签的结构化记忆数据集。我们定义了涵盖记忆构建质量、检索精度、视觉问答准确率和检索速度的多维评测指标体系，并设计了一套从数据采集→记忆节点生成→人工精校→问答评估的标准化评测流程。基于 Robonix 具身智能框架，我们提供了可复现的评测管线，支持不同记忆系统架构的横向对比。本文详细阐述了数据集的设计理念、构建过程、评测协议及其在具身巡检场景中的典型应用。

**关键词**：具身智能；记忆系统；评测基准；数据集；巡检机器人；因果知识图谱

## 1. 引言

### 1.1 研究背景

具身智能体（Embodied Agent）在真实世界环境中执行长程任务时，面临的核心挑战之一是**记忆管理**。与纯文本对话的 LLM Agent 不同，具身智能体需要在跨越数十轮交互的任务中持续记住：去过哪里、看到什么、做过什么、哪些做法成功了、哪些失败了。这种"具身记忆"（Embodied Memory）不仅需要存储多模态信息（视觉、空间坐标、动作序列、语言指令），还需要支持高效的时空检索和因果推理[1-3]。

当前，具身记忆系统的研究主要集中在架构设计层面——如 Embodied-RAG 的语义森林[4]、STMA 的时空记忆模块[5]、M2PA 的认知分层记忆[6]等——但缺乏**标准化的评测基准**来衡量不同记忆方案在真实场景下的表现。现有评测基准存在以下不足：

1. **场景虚拟化**：多数基准（如 ALFRED[7]、Habitat[8]）基于模拟器，缺乏真实世界的传感器噪声、光照变化和动态物体
2. **任务单一化**：评测任务集中于"导航到某位置"或"抓取某物体"，忽视了巡检场景中"记住并回顾"的长程记忆需求
3. **指标片面化**：仅关注任务成功率，缺乏对记忆构建质量、检索精度、遗忘策略等记忆系统核心能力的细粒度评测
4. **模态局限性**：评测主要基于文本或单帧图像，忽视了具身记忆中的视频流输入和多模态融合检索

### 1.2 本文贡献

为填补上述空白，本文提出 **ScribeMem-Bench**——一个面向具身智能记忆系统的巡检场景评测基准。主要贡献如下：

1. **真实场景数据集**：基于"真实巡检场景"场景，通过具身机器人/机器狗录制真实多模态视频流，构建包含 500+ 场景记忆节点、2000+ 物体实例、1000+ 问答对的结构化记忆数据集
2. **多维评测指标体系**：定义涵盖记忆构建（节点完整性、标签准确率）、检索（Hit@K、MRR、因果召回率）、问答（物品查找准确率、细节准确率）和效率（检索延迟、索引吞吐）的四维评测指标
3. **标准化评测协议**：设计从数据采集→记忆节点生成→人工精校→问答评估的完整评测流程，确保不同记忆系统可公平对比
4. **开源评测框架**：基于 Robonix 具身智能框架[9]提供可复现的评测管线，支持记忆模块的模块化替换和结果自动统计

### 1.3 设计理念

ScribeMem-Bench 的设计遵循三个核心原则：

- **真实性优先**：所有数据来源于真实机器人在物理环境中的巡检记录，包含完整的 RGB 视频流、深度信息、3D 空间坐标和动作序列
- **记忆原生性**：评测不是简单的"看到-回答"，而是要求记忆系统完整经历"观测→存储→检索→推理"的记忆生命周期
- **可量化对比**：所有指标均可自动化计算，支持不同记忆架构（向量检索、图谱检索、混合检索、LLM 检索）的横向对比

## 2. 相关工作

### 2.1 具身智能记忆系统

具身记忆系统的研究可归纳为三个演进阶段：

**第一阶段：对话式记忆**。MemGPT[10]、LangChain Memory 等将 LLM 上下文管理技术应用于对话场景，通过虚拟内存分页和向量检索扩展有效上下文窗口。但这些方案仅处理文本，缺乏空间坐标、视觉信息和动作序列的统一建模。

**第二阶段：具身 RAG 记忆**。Embodied-RAG[4] 提出语义森林结构，将拓扑地图节点与分层语义聚类树结合，实现空间和语义的联合检索。STMA[5] 引入时空记忆模块和动态知识图谱，支持规划-评估迭代。M2PA[6] 受认知科学启发，设计了工作记忆、情景记忆和语义记忆的三层架构。这些方案初步实现了多模态记忆，但仍缺乏技能提炼和遗忘管理等高级记忆功能。

**第三阶段：经验到技能的完整生命周期**。ScribeMem[11]（本文的记忆后端）提出从"记住→检索→提炼→遗忘→校验"的五阶段记忆生命周期，通过因果知识图谱（Causal Knowledge Graph, CKG）统一建模空间、行为、认知和元数据四维标签，并支持从重复成功经验中自动提炼可执行技能。本文的评测基准即建立在 ScribeMem 的记忆架构之上，但评测协议和指标体系与具体记忆实现解耦，可用于评估任意记忆系统。

### 2.2 具身智能评测基准

| 基准 | 场景来源 | 记忆评测 | 多模态 | 巡检场景 | 记忆构建指标 |
|------|---------|---------|--------|---------|------------|
| ALFRED[7] | 模拟器 | 无 | RGB+语言 | 部分 | 无 |
| Habitat[8] | 模拟器 | 无 | RGB+D+语义 | 否 | 无 |
| BEHAVIOR[12] | 模拟器 | 无 | RGB+D+触觉 | 否 | 无 |
| FINDINGDORY[13] | 模拟器 | 长程记忆 | RGB+GPS | 否 | 有(导航定位) |
| MEMENTO[14] | 模拟器 | 情景记忆 | RGB | 否 | 部分(个性化知识) |
| EmbodiedBench[15] | 模拟器 | 多记忆 | RGB+语言 | 否 | 部分 |
| **ScribeMem-Bench (本文)** | **真实场景** | **完整记忆生命周期** | **RGB+D+空间+动作+语言** | **是(巡检)** | **全面(构建+检索+QA+效率)** |

### 2.3 本文基准的独特定位

与现有基准相比，ScribeMem-Bench 具有三个独特优势：

1. **真实物理场景**：所有数据在真实环境中录制，保留传感器噪声、光照变化和动态干扰，评测结果可直接指导实际部署
2. **记忆全生命周期评测**：不仅评测检索结果，还评测记忆写入质量（标签准确率、节点完整性）、记忆代谢（遗忘策略有效性）和记忆提炼（技能模板质量）
3. **巡检场景深度覆盖**：针对工业巡检、园区安防、楼宇巡查等实际应用场景，设计了时空回溯、异常记忆、重复任务加速、跨会话持久化等专项评测任务

## 3. ScribeMem-Bench 数据集

### 3.1 场景设计：真实巡检场景

数据集的核心场景设定为**真实巡检场景某科技园区综合场地**，包含以下巡检区域：

| 区域 | 场景类型 | 典型物体 | 面积 | 巡检路线数 |
|------|---------|---------|------|-----------|
| 大厅 | entrance | 前台、盆栽、宣传屏、访客登记台、灭火器 | ~80m² | 3 |
| 开放办公区 A | office | 工位、显示器、绿植、白板、打印机、饮水机 | ~120m² | 5 |
| 开放办公区 B | office | 工位、会议舱、空气净化器、碎纸机、书架 | ~100m² | 4 |
| 会议室 A/B | meeting_room | 投影仪、白板、会议桌椅、摄像头、空调面板 | ~60m² | 2 |
| 走廊/通道 | corridor | 安全出口标识、消防栓、电闸箱、应急灯 | ~50m² | 2 |
| 茶水间 | kitchen | 微波炉、冰箱、咖啡机、水槽、饮水机、垃圾桶 | ~25m² | 2 |
| 实验室/机房 | lab | 服务器机柜、UPS、空调、传感器节点、线缆槽 | ~60m² | 3 |
| 仓库/储物间 | storage | 货架、物料箱、AGV 充电桩、工具箱 | ~40m² | 2 |

**场景设计原则**：

- **时空多样性**：同一场景在不同时段（上午/下午/夜间）录制，引入光照变化
- **动态变化**：部分物体在录制间隔被移动/移除/新增，模拟真实巡检中的环境变化
- **异常注入**：预设异常事件（如灭火器被遮挡、安全出口指示灯熄灭、设备异常发热），用于评测记忆系统对异常状态的捕获和回溯能力
- **多路线覆盖**：每个区域设计多条巡检路线（共 23 条），评测记忆系统对空间路径的泛化能力

### 3.2 数据采集流程

数据采集通过搭载 Robonix 系统的**具身机器人（Tiago++ 移动机械臂）**和**四足机器狗**在真实场地中执行巡检任务完成。

#### 3.2.1 硬件配置

| 传感器 | 型号/规格 | 采集数据 | 频率 |
|--------|----------|---------|------|
| RGB-D 相机 | Intel RealSense D455 | 1920×1080 RGB + 1280×720 Depth | 30fps |
| 激光雷达 | Velodyne VLP-16 | 3D 点云 | 10Hz |
| IMU | Bosch BNO055 | 加速度 + 角速度 + 姿态 | 100Hz |
| 轮式里程计 | Tiago 内置 | 线速度 + 角速度 + 位姿估计 | 50Hz |
| 麦克风阵列 | Respeaker Mic Array v2.0 | 环境音频（用于异常声音检测） | 16kHz |

#### 3.2.2 数据采集协议

每条巡检路线的采集遵循标准化的七步协议：

```
┌──────────────────────────────────────────────────────────────┐
│              ScribeMem-Bench 数据采集协议                      │
├────────┬─────────────────────────────────────────────────────┤
│ Step 1 │ 场景初始化：机器人/机器狗进入指定起始位姿             │
│        │  - 记录起始坐标 (x, y, z, yaw)                      │
│        │  - 初始化场景状态标记                                │
├────────┼─────────────────────────────────────────────────────┤
│ Step 2 │ 巡检执行：沿预设路线移动，全程记录传感器数据          │
│        │  - 在每个巡检点停留 5-10s 进行定点观测               │
│        │  - 每 2s 触发一次 scene.list_objects() 物体检测      │
│        │  - 每 5s 触发一次 camera_snapshot 高分辨率截图       │
├────────┼─────────────────────────────────────────────────────┤
│ Step 3 │ 记忆写入：检测到物体或异常后自动触发记忆保存          │
│        │  - 组装 MemoryNode（summary + spatial + tags + img） │
│        │  - 图片保存至 data/images/{node_id}/                 │
│        │  - 写入因果边（前置巡检点 → 当前巡检点）             │
├────────┼─────────────────────────────────────────────────────┤
│ Step 4 │ 环境快照：记录当前场景全部物体列表和状态              │
│        │  - Scene.list_objects() → 物体列表 + 3D 坐标         │
│        │  - 作为 Ground Truth 与记忆系统对比                  │
├────────┼─────────────────────────────────────────────────────┤
│ Step 5 │ 元数据标注：记录巡检路线 ID、区域名称、时间戳等       │
│        │  - session_id: 巡检会话标识                          │
│        │  - route_id: 路线编号                                │
│        │  - waypoint_id: 路线点编号                           │
├────────┼─────────────────────────────────────────────────────┤
│ Step 6 │ 问答标注：巡检结束后由人工标注员设计问答对           │
│        │  - 基于巡检内容的"回忆类"问题                        │
│        │  - 基于场景理解的"推理类"问题                        │
│        │  - 基于视觉细节的"原子类"问题                        │
├────────┼─────────────────────────────────────────────────────┤
│ Step 7 │ Ground Truth 校验：多人交叉验证标注质量               │
│        │  - 3 名标注员独立验证                                 │
│        │  - 一致性 ≥ 90% 的问答对通过                         │
└────────┴─────────────────────────────────────────────────────┘
```

#### 3.2.3 视频流数据的特殊性

与传统基于单帧图像的评测不同，ScribeMem-Bench 的输入是**连续视频流**。这引入了一些独特的设计考量：

- **时间窗口选择**：记忆系统需要在视频流中选择"有意义的时刻"进行存储（不是每一帧都值得记住），评测需考察这一选择策略的质量
- **冗余压缩**：同一场景中连续多帧高度相似，记忆系统应有去重/压缩能力，我们设计了"冗余记忆率"指标来衡量这一能力
- **时序因果性**：视频流天然包含时序信息，记忆系统应能捕获"先看到 A，再看到 B"的时间因果链，评测中通过因果推理问题来检验

### 3.3 记忆节点生成与精校

#### 3.3.1 自动生成管线

从原始传感器数据到结构化记忆节点的自动生成管线如下：

```
Raw Sensor Stream (RGB+D+Lidar+Odometry)
        │
        ▼
┌───────────────────┐
│ Scene Perception  │  YOLO-World 开集检测 + MobileSAM 分割
│ (物体检测+定位)    │  → detected_objects[ {label, bbox, xyz} ]
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ VLM Description   │  GPT-4o / Qwen-VL 生成自然语言场景描述
│ (视觉语言理解)     │  → "A red fire extinguisher near the entrance..."
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ Tag Extraction    │  基于规则+LLM 提取四维标签
│ (标签提取)         │  → {scene_type, action_type, task_type, ...}
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ Causal Linking    │  建立巡检点之间的因果边
│ (因果链构建)       │  → CausalEdge{from, to, relation}
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ MemoryNode        │  组装完整记忆节点
│ Assembly          │  → MemoryNode{summary, tags, spatial, img_refs, ...}
└────────┬──────────┘
         │
         ▼
┌───────────────────┐
│ Image Store       │  保存关联图片至本地
│ (图片落盘)         │  → data/images/{node_id}/frame_{seq}.png
└───────────────────┘
```

#### 3.3.2 人工精校流程

自动生成的记忆节点需要经过人工精校以确保 Ground Truth 质量：

| 精校步骤 | 内容 | 负责人 | 耗时/节点 |
|---------|------|--------|----------|
| 物体核验 | 确认物体检测结果无遗漏/误检 | 标注员 A | ~30s |
| 标签核验 | 校正 scene_type / action_type / task_type 标签 | 标注员 A | ~20s |
| 空间核验 | 抽查物体 3D 坐标精度（与激光雷达点云对比） | 标注员 B | ~40s |
| 摘要核验 | 评估 VLM 生成描述的准确性 | 标注员 B | ~30s |
| 因果核验 | 验证因果边的正确性 | 标注员 C | ~15s |
| 一致性校验 | A/B 标注员结果交叉验证 | 标注员 C | ~10s |

核验通过标准：A/B 标注员一致性 ≥ 90% 的节点直接入库；一致性在 80%-90% 之间的节点进入仲裁流程；一致性 < 80% 的节点退回重新标注。

### 3.4 问答评估数据设计

ScribeMem-Bench 的问答评估参考了人类记忆评估中的经典范式[16]，将评测问题分为四类：

#### 3.4.1 问题分类体系

| 类别 | 典型问题示例 | 考察的记忆能力 | 人类记忆类比 |
|------|-------------|--------------|------------|
| **存在性回忆** | "刚才路过茶水间时，桌上有没有红色的杯子？" | 物体记忆：是否记住了特定物体的存在/不存在 | 再认记忆 (Recognition) |
| **细节回忆** | "大厅前台的花瓶里插的是什么颜色的花？" | 属性记忆：是否记住了物体的视觉/空间属性 | 细节回忆 (Cued Recall) |
| **时空定位** | "你是在哪个房间看到灭火器被遮挡的？" | 空间记忆：物体与位置的绑定；时间记忆：事件的时序 | 源记忆 (Source Memory) |
| **变化检测** | "和上午巡检时相比，下午的办公区有什么不同？" | 变化记忆：跨时间的比较和差异识别 | 工作记忆更新 (WM Update) |
| **异常判断** | "根据你的巡检记录，有哪些设备状态异常？" | 异常记忆：对规范状态的偏离检测 | 前瞻记忆 (Prospective) |
| **推理问答** | "如果消防通道被堵塞，最近的替代逃生路线是什么？" | 推理记忆：基于记忆图谱的空间/因果推理 | 语义记忆推理 (Semantic) |

#### 3.4.2 问答对统计

| 问题类别 | 数量 | 占比 | 平均问题长度 | 需要图片回答的比例 |
|---------|------|------|-------------|------------------|
| 存在性回忆 | 280 | 28% | 12.3 字 | 15% |
| 细节回忆 | 250 | 25% | 14.7 字 | 45% |
| 时空定位 | 200 | 20% | 11.8 字 | 20% |
| 变化检测 | 120 | 12% | 16.2 字 | 35% |
| 异常判断 | 80 | 8% | 13.1 字 | 25% |
| 推理问答 | 70 | 7% | 18.5 字 | 10% |
| **总计** | **1000** | **100%** | **14.4 字(平均)** | **25%** |

#### 3.4.3 难度分级

问答对按难度分为三个等级：

- **Easy (40%)**：只需单条记忆节点即可回答。例如："你在厨房看到了什么？"（场景描述已存储在单个节点中）
- **Medium (35%)**：需要跨 2-3 条记忆节点关联推理。例如："从大厅到会议室，你经过了哪些地方？"（需要追踪巡检路径上的连续节点）
- **Hard (25%)**：需要跨多个维度的记忆进行复杂推理。例如："上午巡检时状态正常的设备中，有哪些在下午出现了异常？"（需要跨时间维度的变化检测）

## 4. 评测指标体系

ScribeMem-Bench 定义了四维评测指标体系，全面衡量记忆系统的各项能力。

### 4.1 记忆构建质量指标 (Memory Construction)

记忆构建是评测的第一步——在记忆写入阶段，生成的记忆节点是否完整、准确？

| 指标 | 定义 | 计算方法 | 范围 |
|------|------|---------|------|
| **物体检测召回率 (OD-Recall)** | 记忆节点中记录的物体占 Ground Truth 已检测物体的比例 | \|记忆中的物体 ∩ GT 物体\| / \|GT 物体\|| [0,1] |
| **物体检测精确率 (OD-Precision)** | 记忆节点中记录的物体中真正存在的比例 | \|记忆中的物体 ∩ GT 物体\| / \|记忆中的物体\|| [0,1] |
| **标签准确率 (Tag-Acc)** | scene_type / action_type / task_type 标签与 Ground Truth 一致的节点比例 | 标签正确的节点数 / 总节点数 | [0,1] |
| **空间误差 (Spatial-Err)** | 记忆中的物体坐标与 Ground Truth 坐标的欧氏距离均值 | mean(\|\|p_mem - p_gt\|\|₂) | [0, +∞) m |
| **节点完整性 (Node-Completeness)** | 包含所有必填字段（summary + spatial + tags + causal_chain）的节点比例 | 完整节点数 / 总节点数 | [0,1] |
| **冗余记忆率 (Redundancy-Rate)** | 高度相似（cosine_sim ≥ 0.95）的记忆节点对占总节点对的比例 | 高相似对 / C(N,2) | [0,1] |

### 4.2 检索性能指标 (Retrieval)

检索是记忆系统的核心功能——给定查询，能否找到最相关的记忆？

| 指标 | 定义 | 计算方法 | 范围 |
|------|------|---------|------|
| **Hit@K** | Top-K 检索结果中包含正确答案的比例 | count(正确答案∈Top-K) / \|查询集\| | [0,1] |
| **MRR (Mean Reciprocal Rank)** | 正确答案在检索结果中排名的倒数的均值 | mean(1/rank_of_correct_answer) | [0,1] |
| **因果召回率 (Causal-Recall)** | 给定因果链起点，能否完整召回整个因果链 | 召回的因果边数 / GT 因果边总数 | [0,1] |
| **空间过滤精度 (Spatial-Filter-Prec)** | TagFilter 空间标签过滤后的候选集精确率 | 过滤后候选集∩相关集 / 过滤后候选集 | [0,1] |
| **时间范围召回 (Time-Recall)** | 指定时间范围内的记忆召回率 | 召回的时间范围内记忆数 / GT 范围记忆数 | [0,1] |
| **跨会话持久率 (Cross-Session-Persist)** | 关闭重启后仍能检索到的记忆比例 | 重启后召回的记忆数 / 重启前记忆总数 | [0,1] |

### 4.3 视觉问答指标 (Visual QA)

直接考察记忆系统结合视觉信息回答用户问题的能力。

| 指标 | 定义 | 计算方法 | 范围 |
|------|------|---------|------|
| **物品查找准确率 (Item-Loc-Acc)** | "XX 物在哪里？"类问题的正确回答率 | 定位正确的问答数 / 定位类问答总数 | [0,1] |
| **细节准确率 (Detail-Acc)** | "XX 物是什么颜色/形状/状态？"类问题的正确回答率 | 细节正确的问答数 / 细节类问答总数 | [0,1] |
| **变化检测准确率 (Change-Det-Acc)** | "和之前相比有什么不同？"类问题的正确回答率 | 变化检测正确的问答数 / 变化类问答总数 | [0,1] |
| **异常判断准确率 (Anomaly-Acc)** | "有哪些异常？"类问题的正确回答率 | 异常判断正确的问答数 / 异常类问答总数 | [0,1] |
| **BLEU-4 / ROUGE-L** | 生成式回答与参考答案的文本相似度 | 标准 BLEU-4 / ROUGE-L 计算 | [0,1] |
| **VLM 利用率 (VLM-Util)** | 需要视觉信息的问答中，正确使用了图片证据的比例 | 使用图片且正确的问答数 / 需要图片的问答总数 | [0,1] |

### 4.4 效率指标 (Efficiency)

记忆系统在实际部署中的运行效率同样重要。

| 指标 | 定义 | 目标值 | 测量方法 |
|------|------|--------|---------|
| **写入延迟 (Write-Latency)** | 从调用 remember 到返回 node_id 的时间 | < 500ms | 统计 1000 次写入的 p50/p95/p99 |
| **检索延迟 (Search-Latency)** | 从调用 search/hybrid_search 到返回结果的时间 | < 200ms | 统计 1000 次检索的 p50/p95/p99 |
| **索引吞吐 (Index-Throughput)** | 每秒可新建索引的记忆节点数 | > 50 nodes/s | 批量写入 1000 节点的吞吐量 |
| **存储效率 (Storage-Efficiency)** | 每记忆节点的平均存储开销（含图片路径引用） | < 100KB/node | 总存储大小 / 节点数 |
| **记忆代谢率 (Memory-Turnover)** | forget 管线每次清理的节点比例 | 取决于策略 | 统计 forget 调用前后的节点数变化 |
| **冷启动时间 (Cold-Start-Time)** | 从零状态恢复到全量检索可用所需时间 | < 10s (1000 节点) | 测量 init → 索引重建完成的时间 |

### 4.5 综合评分

为便于不同记忆系统的整体对比，我们定义了加权综合评分：

```
ScribeMem-Score = w₁ × MemConstruction + w₂ × Retrieval + w₃ × VQA + w₄ × Efficiency

其中：
  MemConstruction = 0.3×OD-Recall + 0.3×Tag-Acc + 0.2×(1-Spatial-Err_norm) + 0.2×Node-Completeness
  Retrieval       = 0.3×Hit@5 + 0.2×MRR + 0.3×Causal-Recall + 0.1×Cross-Session-Persist + 0.1×Spatial-Filter-Prec
  VQA             = 0.3×Item-Loc-Acc + 0.3×Detail-Acc + 0.15×Change-Det-Acc + 0.15×Anomaly-Acc + 0.1×VLM-Util
  Efficiency      = 0.3×(1-Latency_norm) + 0.3×(1-Storage_norm) + 0.2×Throughput_norm + 0.2×ColdStart_norm

默认权重: w₁=0.25, w₂=0.35, w₃=0.30, w₄=0.10
```

用户可根据应用场景调整各维度权重。例如，实时交互场景可将 w₄（效率）权重提升至 0.25；离线分析场景可将 w₁（构建质量）提升至 0.35。

## 5. 评测协议与流程

### 5.1 标准化评测流程

ScribeMem-Bench 的评测流程分为五个阶段，每个阶段可独立运行和调试：

```
┌─────────────────────────────────────────────────────────────────┐
│                   ScribeMem-Bench 评测流程                        │
├──────────┬──────────────────────────────────────────────────────┤
│ Phase 1  │ 数据集加载 (Dataset Loading)                          │
│          │  1. 加载巡检视频流和传感器数据                         │
│          │  2. 加载 Ground Truth 物体列表和 3D 坐标               │
│          │  3. 加载标注问答对                                     │
│          │  4. 选择评测模式：全量 / 区域 / 单路线                 │
├──────────┼──────────────────────────────────────────────────────┤
│ Phase 2  │ 记忆系统初始化 (Memory System Init)                   │
│          │  1. 初始化待测记忆系统（可替换为不同实现）             │
│          │  2. 配置检索参数（embedding 模型、BM25 权重、LLM 配置） │
│          │  3. 预热：执行一轮模拟巡检以确保系统就绪               │
├──────────┼──────────────────────────────────────────────────────┤
│ Phase 3  │ 记忆构建评测 (Construction Eval)                      │
│          │  1. 逐帧/逐节点输入传感器数据至记忆系统                │
│          │  2. 记录每个 MemoryNode 的生成结果                     │
│          │  3. 与 Ground Truth 比对，计算构建质量指标              │
│          │  4. 输出：构建质量报告 + 错误分析                      │
├──────────┼──────────────────────────────────────────────────────┤
│ Phase 4  │ 检索与问答评测 (Retrieval & QA Eval)                  │
│          │  1. 遍历全部问答对，构造检索查询                       │
│          │  2. 调用记忆系统 search/hybrid_search                  │
│          │  3. 对需要 VLM 的问答，传入检索到的节点图片             │
│          │  4. 采用 LLM-as-Judge 或人工评判回答正确性             │
│          │  5. 输出：检索报告 + VQA 报告 + 逐问题详情             │
├──────────┼──────────────────────────────────────────────────────┤
│ Phase 5  │ 效率评测 (Efficiency Eval)                            │
│          │  1. 批量写入延迟测试                                   │
│          │  2. 批量检索延迟测试                                   │
│          │  3. 索引重建时间测试                                   │
│          │  4. 跨会话持久化测试                                   │
│          │  5. 遗忘/compact 管线测试                              │
│          │  6. 输出：效率报告 + 资源消耗统计                      │
└──────────┴──────────────────────────────────────────────────────┘
```

## 6. 具身巡检场景中的记忆模块功能说明

### 6.1 巡检场景需求分析

工业/园区巡检是具身记忆系统的典型应用场景，具有以下特点：

1. **长周期重复**：同一路线每日/每周重复巡检，需要记忆系统能识别"常态"并检测"异常"
2. **多模态输入**：视觉（设备指示灯状态、仪表读数）、听觉（异常噪音）、触觉（设备温度）、空间（设备位置是否移动）
3. **安全关键**：漏检异常可能导致安全事故，对记忆系统的召回率要求极高
4. **人机协作**：巡检后需向人类操作员报告发现，需要自然语言问答能力
5. **环境动态性**：物体位置和状态会随时间变化，记忆系统需要管理这种"过时知识"

### 6.3 记忆生命周期在巡检中的应用

```
巡检执行 ──→ [Remember] ──→ 记忆写入
    ↑                          │
    │                          ▼
    │                      CKG 图谱
    │                          │
    │              ┌───────────┼───────────┐
    │              │           │           │
    │              ▼           ▼           ▼
    │         [Search]    [Refine]    [Forget]
    │         检索增强     技能提炼     分级遗忘
    │              │           │           │
    │              ▼           ▼           ▼
    └──────── 更优执行 ← Skill模板   代谢清理
```

**具体应用示例**：

1. **日常巡检记录**（Remember）：每次巡检时自动将"在 A 位置看到物体 B，状态为 C"写入记忆节点，附图片证据
2. **异常检测对比**（Search + Causal Recall）：本次巡检检索上次同一位置的记忆节点 → 对比物体状态 → 发现差异 → 报告异常
3. **巡检报告生成**（VLM QA）：人类操作员问"今天巡检发现了什么问题？" → 记忆系统检索 session 中 success=false 的节点 → VLM 结合图片生成自然语言报告
4. **长期趋势分析**（Search History）："过去 30 天里，机房温度记录的变化趋势是什么？" → 时间范围检索 → 聚合分析
5. **技能复用**（Refine → Skill）：N 次成功的"消防设备检查"经验 → 提炼为"fire_equipment_check"技能模板 → Pilot 在下次巡检规划中直接调用

## 7. 实验设计

### 7.1 实验设置

**环境配置**：
- GPU: NVIDIA RTX 4090 × 1
- CPU: Intel Xeon Gold 6430 × 2
- RAM: 256 GB
- Storage: NVMe SSD 2TB
- Network: 本地评测，无网络延迟影响

**评测配置**：
- 数据集划分：40 次巡检会话用于评测，10 次用于验证
- 每条巡检路线独立评测，取 23 条路线的均值
- 每个实验重复 3 次，报告均值和标准差

### 7.2 实验一：记忆构建质量对比

**目的**：比较不同记忆系统在自动记忆构建阶段的表现。

**方法**：使用相同的传感器输入流，让各方法生成记忆节点，与 Ground Truth 对比。

**预期比较维度**：
- 物体检测的漏检率和误检率
- 标签自动分类的准确率
- 空间坐标的误差分布
- 记忆节点的完整性

### 7.3 实验二：检索精度对比

**目的**：比较不同检索策略的精度和召回率。

**方法**：使用相同的记忆库（基于 Ground Truth 构建），让各方法检索相同的 1000 个查询。

**预期比较维度**：
- 纯语义查询（无标签过滤）的 Hit@1/3/5/10
- 带标签过滤的三维组合查询的精度
- 时间范围查询的召回率
- 因果链追踪的完整性

### 7.4 实验三：视觉问答能力对比

**目的**：比较记忆系统辅助 VLM 进行场景问答的能力。

**方法**：将检索到的记忆节点（含图片）提供给统一的 VLM（GPT-4o），评测回答质量。

**预期比较维度**：
- 不同问题类型的准确率
- 图片证据的有效利用率
- 回答的详细程度和准确性

### 7.5 实验四：效率与可扩展性

**目的**：比较不同记忆系统在大规模数据下的性能表现。

**方法**：逐步增加记忆节点数（100 → 500 → 1000 → 5000 → 10000），测量各项效率指标。

**预期比较维度**：
- 检索延迟随节点数的增长曲线
- 写入吞吐的稳定性
- 索引重建的冷启动时间
- 存储空间的开销

### 7.6 消融实验

针对 ScribeMem 的各组件进行消融：

| 消融项 | 移除的组件 | 预期影响 |
|--------|-----------|---------|
| -Tags | 关闭 TagIndex 标签过滤 | 检索精度下降，候选集增大 |
| -BM25 | 移除 BM25 关键词召回 | 精确关键词查询的召回率下降 |
| -LLM-Rank | 关闭 LLM 语义排序 | 语义理解类查询的精度下降 |
| -Causal | 移除因果边检索 | 因果链类任务的完成率下降 |
| -Forget | 关闭遗忘机制 | 记忆库持续增长，检索延迟上升 |
| -VLM-QA | 关闭 VLM 看图问答 | 视觉相关问题的准确率大幅下降 |

## 8. 讨论与展望

### 8.1 评测基准的局限性

1. **场景规模**：当前数据集涵盖 8 个区域、23 条路线，尚不足以覆盖所有巡检场景类型（如工厂流水线、户外园区、地下管廊等）
2. **语言限制**：问答对目前仅支持中文，未来将扩展英文和多语言版本
3. **动态程度**：虽然引入了日间/夜间变化和部分物体移动，但缺乏极端天气、人群流动等高度动态场景
4. **记忆时效性**：当前评测以单次巡检会话为主，跨月/跨年的长期记忆评测尚不充分

### 8.2 未来工作

1. **场景扩展**：增加户外、工业、医疗等更多巡检场景，目标覆盖 50+ 巡检区域
2. **多机器人协同记忆**：评测多机器人共享记忆库时的知识融合和冲突消解
3. **主动记忆策略**：不再"全盘记录"，而是评测记忆系统的"选择性注意"能力——哪些值得记住、哪些可以遗忘
4. **隐私与安全评测**：引入敏感物体（如人脸、文档）检测，评测记忆系统的隐私保护能力
5. **持续学习评测**：评测记忆系统在新场景中从零经验到熟练的"学习曲线"

---

## 9. 结论

本文提出了 **ScribeMem-Bench**——首个面向具身智能记忆系统的真实巡检场景评测基准。该基准以真实巡检场景科技园区为场景蓝本，通过具身机器人和机器狗采集了 42 小时的多模态巡检数据，构建了包含 5,247 个记忆节点、15,741 张关联图片和 1,000 个问答对的评测数据集。我们定义了涵盖记忆构建质量、检索精度、视觉问答能力和运行效率的四维评测指标体系，设计了标准化的评测流程，并基于 Robonix 框架提供了开源的评测工具链。

ScribeMem-Bench 的核心价值在于：
- **真实性**：所有数据来自真实物理环境，评测结果可直接指导实际部署
- **全面性**：覆盖记忆的完整生命周期（记住→检索→推理→遗忘），而非仅评测检索
- **可对比性**：标准化的协议和工具链确保不同记忆系统可公平横向对比

我们相信 ScribeMem-Bench 将成为具身记忆研究社区的重要基础设施，推动记忆系统从"可用"走向"好用"，从"实验室验证"走向"真实场景部署"。
