六类问答的说明：

┌─────────────────────┬────────────────────────────────┬──────────────────┐

│ 类别                │ 考察内容                       │ 人类记忆类比     │

├─────────────────────┼────────────────────────────────┼──────────────────┤

│ existence\_recall    │ "物体X在场景Y中是否存在？"     │ 再认记忆         │

│ detail\_recall       │ "物体X的属性是什么？"           │ 线索回忆         │

│ spatiotemporal      │ "你在哪里/何时看到了X？"       │ 源记忆           │

│ change\_detection    │ "两次巡检之间有什么不同？"     │ 工作记忆更新     │

│ anomaly\_judgment    │ "有哪些设备/状态异常？"        │ 前瞻记忆         │

│ reasoning           │ "基于巡检记录进行空间/因果推理" │ 语义记忆推理     │

└─────────────────────┴────────────────────────────────┴──────────────────┘



六类问答的共同字段：

qa\_id               唯一标识（前缀 E/D/S/C/A/R \+ 编号）

category            类别名

difficulty          难度: easy \| medium \| hard

session\_ids\[\]       依赖的巡检会话 ID 列表

related\_node\_ids\[\]  关联的记忆节点 ID 列表

related\_object\_ids\[\] 关联的物体 GT ID 列表

requires\_image      是否需要加载图片给 VLM

image\_refs\[\]        需要的图片文件路径（仅 requires\_image=true 时有值）

requires\_video       是否需要加载视频片段给 VLM（可选，默认 false）

video\_clip\_range\{\}   需要的视频片段范围（仅 requires\_video=true 时有值，含 video\_id \+ start\_ts/end\_ts）

question\_zh / question\_en   中英双语问题

answer\_zh / answer\_en       中英双语参考答案

answer\_type         答案类型: boolean \| single\_attribute \| multi\_object\_list \|

location\_name \| waypoint\_index \| distance\_value \|

ordered\_list \| change\_description \| trend\_analysis \|

anomaly\_description \| ranked\_list \| causal\_inference \|

emergency\_plan \| anomaly\_discovery

evidence\_zh / evidence\_en    答案依据（可溯源至具体 node / frame）

acceptable\_answers\_zh\[\] / acceptable\_answers\_en\[\]  可接受的等效答案列表

notes               补充说明（可选）



难度分级标准：

Easy    — 单节点直接可答，答案在 summary 或 tags 中显式存在

Medium  — 需跨 2\-3 节点关联，或答案在 image 中需 VLM 提取

Hard    — 需跨多节点综合推理，或涉及因果链，或需发现隐性异常



各类别特有字段：

existence\_recall:     answer\_type=boolean, negative\_distractors\[\]（易混淆物体ID列表）

detail\_recall:        attribute\_key（查询的具体属性名）, requires\_image 多为 true

spatiotemporal:       spatial\_constraint\{\} / temporal\_constraint\{\}（查询的时空约束）

change\_detection:     session\_ids 长度 ≥2, change\_type（变化类型枚举）

anomaly\_judgment:     anomaly\_type, severity: info\|warning\|critical

reasoning:            reasoning\_type（推理类型枚举）

附录 H：视频流数据规范

═══════════════════════════════════════════════════════════════



简要说明：每次巡检会话可包含多路视频流（RGB/Depth/Thermal），视频流是图像帧的

连续录制容器，与 images/ 目录中的抽取帧一一对应。视频流用于：

\(a\) 提供帧间时序上下文（相邻帧间的运动/变化信息）

\(b\) 支持基于视频的 VLM 方法（如 Video\-LLaMA、Gemini\-Video 等）

\(c\) 在评测中验证帧间一致性



字段结构（videos\_index\.csv）：

video\_id            视频流唯一标识 "vid\_\{session\_id\}\_\{camera\_type\}\_\{seq\}"

file\_path           视频文件相对路径（如 session\_001/videos/rgb\_main\.mp4）

camera\_type         相机类型: rgb \| depth \| thermal \| rgb\_stereo\_left \| rgb\_stereo\_right

codec               编码格式: h264 \| h265 \| raw \| zstd\_compressed

resolution          分辨率 "W×H"（如 "1920×1080"）

fps                 帧率（如 30\.0）

duration\_sec        视频时长（秒）

start\_ts / end\_ts   u64, 视频起始/结束时间戳（chronos 纳秒）

start\_frame\_id / end\_frame\_id  对应 images\_index\.csv 中的帧 ID 范围



视频文件目录结构：

session\_NNN/videos/

├── rgb\_main\.mp4          \# RGB 主摄像头视频流

├── rgb\_stereo\_left\.mp4   \# RGB 立体左目（如有）

├── rgb\_stereo\_right\.mp4  \# RGB 立体右目（如有）

├── depth\_aligned\.mp4     \# 对齐到 RGB 的深度视频流

└── thermal\.mp4           \# 红外热成像视频流（如有）



视频 ↔ 图像帧对应关系：

- 图像帧按照固定帧率从视频流中抽取（默认 1 fps，可通过 meta\.yaml 配置）

- images\_index\.csv 中的 frame\_id 对应视频流中的帧序号:

video\_frame\_number = \(frame\_ts \- video\_start\_ts\) / \(1e9 / fps\)

- depth\_index\.csv 中的 depth 帧与 RGB 帧时间戳对齐

    

视频元数据（扩展 meta\.yaml）：

sensor\_configs:

video:

rgb:

enabled: true

codec: "h264"

resolution: "1920×1080"

fps: 30\.0

bitrate\_mbps: 20

sample\_fps: 1\.0          \# 帧抽取帧率（用于 images/ 目录生成）

rgb\_stereo:

enabled: false

depth:

enabled: true

codec: "zstd\_compressed" \# 深度视频采用无损压缩

resolution: "640×480"

fps: 30\.0

depth\_unit: "mm"         \# 深度值单位

aligned\_to: "rgb"        \# 与 RGB 对齐

thermal:

enabled: false

resolution: "320×240"

fps: 9\.0



视频评估相关说明：

- 评测框架默认使用 images/ 中的抽取帧；若方法需要视频输入，则通过

videos\_index\.csv 中的映射关系加载视频片段

- 变化检测（change\_detection）和异常判断（anomaly\_judgment）类 QA 可

选择性地标记 `requires_video: true` 和 `video_clip_range` 字段，

指定评测时需要加载的视频片段范围

- 视频流的存在使得 ScribeMem\-Bench 可以评测基于视频理解的记忆方法

（如 Video\-RAG、Streaming\-VLM 等），扩展了评测维度

附录 I：camera\_calib\.yaml — 相机标定参数

═══════════════════════════════════════════════════════════════



简要说明：每次巡检会话的传感器标定参数，定义各路相机的内参、外参及对齐关系。

MemoryNode 中的 `camera_params` 字段从此文件派生当前时刻的相机状态（与

camera\_pose 结合可得该帧的完整相机外参）。



字段结构：

rgb:                    RGB 主摄像头

fx, fy, cx, cy         针孔模型内参

width, height          图像分辨率

distortion\[\]           畸变系数 \[k1, k2, p1, p2, k3\]（OpenCV 格式）

frame\_rate             采集帧率

depth:                  深度摄像头

fx, fy, cx, cy         内参（通常与 RGB 不同分辨率）

width, height          深度图分辨率

depth\_scale            深度值 → 米 的换算因子（如 0\.001 表示 mm 单位）

aligned\_to             "rgb" \| "none" — 是否已与 RGB 对齐

distortion\[\]           畸变系数

rgb\_stereo:             立体 RGB（如有）

left: \{fx, fy, cx, cy, width, height, distortion\[\]\}

right: \{fx, fy, cx, cy, width, height, distortion\[\]\}

baseline\_m             基线长度（米）

R\[\]                    右目 → 左目旋转矩阵（3×3 行主序）

T\[\]                    右目 → 左目平移向量 \[tx, ty, tz\]（米）

thermal:                红外热成像（如有）

fx, fy, cx, cy

width, height

distortion\[\]

frame\_rate

extrinsics:             各相机到机器人基座的变换（用于多相机融合）

rgb\_to\_base: \{x, y, z, qx, qy, qz, qw\}

depth\_to\_base: \{x, y, z, qx, qy, qz, qw\}

thermal\_to\_base: \{x, y, z, qx, qy, qz, qw\}（如有）



与 MemoryNode 的关系：

- MemoryNode\.camera\_params 记录该节点生成时刻的相机状态（内参 \+ 外参），

外参由 camera\_calib\.yaml 的相机→基座变换 × 基座当时的 odometry 位姿计算得到

- 评测框架通过 camera\_params 可以将节点中的 2D 像素坐标反投影到 3D，

验证物体空间标注的准确性（Spatial\-Err 指标）

- 深度帧可以通过 depth\_scale × depth\_refs 中的像素值还原真实距离

附录 J：QA 设计核心原则

═══════════════════════════════════════════════════════════════



1. 分层组织

    - 场景级 QA（Questions/）: 跨会话综合评测（变化检测、趋势分析、全局推理）

    - 会话级标注（session\_NNN/）: 单次巡检 Ground Truth（objects\.yaml \+ events\.yaml）

    - 节点级数据（memory\_nodes\.json）: 最小评测单元

        

2. 多模态依赖标记

    - requires\_image → 评测框架据此决定是否加载图片给 VLM

    - image\_refs → 精确指定需要的图片帧（避免全量加载）

        

3. 可接受答案列表

    - acceptable\_answers 提供多种等效表述，用于 LLM\-as\-Judge 语义等价判断

    - 中英版本各有独立列表

        

4. 混淆/负样本设计

    - negative\_distractors: 标记易混淆的相似物体 ID

    - confusion\_pairs\.json: MCI 评测的 200 对专门混淆集

        

5. 评测友好性

    - related\_node\_ids / related\_object\_ids → 精确加载依赖，避免全量扫描

    - evidence 字段 → 失败时按 evidence 追溯错误来源（感知/检索/VLM）
